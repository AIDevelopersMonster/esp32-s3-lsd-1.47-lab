# Project Resources

Этот раздел предназначен для изучения **сторонних проектов, примеров, демонстраций и идей** для Waveshare ESP32-S3-LCD-1.47 и близких ESP32-S3-плат.

Цель — не собирать чужие исходники в публичном репозитории, а понять:

- что именно сделал автор;
- какую задачу решает проект;
- зачем такое приложение вообще нужно;
- какие возможности ESP32-S3-LCD-1.47 оно использует;
- насколько проект переносим на нашу плату;
- что можно проверить на реальном железе;
- какие идеи можно использовать **по мотивам**, уже в собственном проекте KONTAKTS/Lab.

## Что публикуем в GitHub

Для каждого изучаемого проекта публикуется только наша исследовательская карточка:

- название проекта;
- автор / организация;
- полная ссылка на оригинальный источник;
- лицензия, если она явно указана;
- краткое описание назначения;
- используемые функции платы;
- заметки о сборке и запуске;
- отличия от нашей Waveshare ESP32-S3-LCD-1.47;
- результат проверки на реальном железе;
- ссылка на наше демонстрационное видео;
- идеи для собственного независимого проекта.

Чужой исходный код, архивы и бинарники здесь по умолчанию **не публикуются**.

## Где держать скачанные исходники локально

Для локального исследования предусмотрена папка:

```text
Project Resources/
  _local/
```

Она исключена из Git через локальный `.gitignore` этого раздела.

Рекомендуемая структура:

```text
Project Resources/
├── README.md
├── _TEMPLATE.md
├── .gitignore
├── projects/
│   └── project-name/
│       └── README.md          <- публикуемая исследовательская карточка
└── _local/                    <- НЕ публикуется
    └── project-name/
        ├── source/            <- скачанный оригинальный проект
        ├── modified/          <- локальные изменения для запуска
        └── notes/             <- временные технические файлы
```

> Важно: файл, который **закоммичен** в обычную ветку Git, при последующем `push` может попасть на GitHub. Поэтому сторонние исходники, которые мы не хотим публиковать, должны оставаться в `_local/` и не добавляться через `git add -f`.

## Порядок исследования нового проекта

1. Найти оригинальный проект, статью, видео или репозиторий.
2. Зафиксировать **прямую ссылку на оригинал** и автора.
3. Проверить, указана ли лицензия и что она разрешает.
4. Создать публичную карточку по шаблону [`_TEMPLATE.md`](_TEMPLATE.md).
5. При необходимости скачать исходники только в `_local/<project-name>/source/`.
6. Сначала понять архитектуру проекта: дисплей, кнопки, Wi-Fi, SD, USB, датчики, LVGL и т. п.
7. Не переносить код вслепую. Отдельно определить, какие GPIO и аппаратные предположения отличаются от нашей платы.
8. Собрать локальную копию и, если это безопасно, проверить на реальной ESP32-S3-LCD-1.47.
9. Записать результат: `NOT_TESTED`, `BUILD_VERIFIED`, `HARDWARE_VERIFIED`, `PARTIAL` или `NOT_COMPATIBLE`.
10. Снять короткое видео с демонстрацией и в описании обязательно дать ссылку на оригинальный источник.
11. Отдельно сформулировать: **что в этой идее полезно для нашего собственного проекта**, не выдавая чужую работу за свою.

## Принцип «по мотивам»

Задача этого раздела — не делать коллекцию копий.

После разбора стороннего проекта мы отделяем:

```text
чужая конкретная реализация
          ↓
какую проблему она решает
          ↓
какой общий инженерный принцип в ней интересен
          ↓
что позволяет наша плата
          ↓
собственная архитектура и собственный код
```

Например, если сторонний проект показывает файловый браузер на маленьком LCD,
интерес для нас может быть не в копировании его UI, а в идее:

- навигации по microSD;
- компактной модели меню;
- предпросмотра файлов;
- сочетания кнопки BOOT и экранного интерфейса;
- последующего создания собственного автономного инструмента.

## Статусы проверки

| Статус | Значение |
|---|---|
| `REFERENCE_ONLY` | изучена только идея / описание |
| `NOT_TESTED` | исходник найден, но ещё не собирался |
| `BUILD_VERIFIED` | проект или адаптация успешно собраны |
| `HARDWARE_VERIFIED` | реально запущено на нашей плате |
| `PARTIAL` | работает только часть функций |
| `NOT_COMPATIBLE` | выявлена существенная несовместимость |

## Видео

В каждом нашем видео по стороннему проекту желательно явно разделять три вещи:

1. **оригинальный проект и его автор**;
2. **наша проверка/адаптация на Waveshare ESP32-S3-LCD-1.47**;
3. **наши дальнейшие идеи**, если на основе общего принципа будет создан собственный проект.

Минимум в описании видео:

```text
Original project:
<полная ссылка на оригинал>

Our ESP32-S3-LCD-1.47 lab:
https://github.com/AIDevelopersMonster/lab-esp32-s3-lcd-1.47
```

Так сохраняется provenance: зрителю понятно, где оригинал, что проверяли мы и что является уже нашей самостоятельной разработкой.
